# Internationalisation (vi / en)

The site is bilingual with **Vietnamese as the default**. English is a full
translation, not a fallback. One dictionary, one hook, one toggle.

---

## 1. How it works

`src/context/LanguageContext.tsx`

```tsx
type Language = "vi" | "en";

const translations = {
    vi: { "nav.home": "Trang Chủ", /* … */ },
    en: { "nav.home": "Home",     /* … */ },
};

const t = (key: string) => {
    const value = translations[language] as Record<string, string>;
    return value[key] ?? key;
};
```

- `LanguageProvider` holds `useState<Language>("vi")`.
- On mount it reads `localStorage.getItem("language")` and applies it if present.
- `setLanguage` writes the choice back to `localStorage` under the key
  `language`. Keys are flat strings, not nested objects.
- `t()` **returns the key itself** when a translation is missing. There is no
  dev warning, no throw, no console output. A typo renders as
  `hero.descripton` in the UI and passes lint, typecheck and build.
- `useLanguage()` throws if used outside the provider. `Providers` mounts it
  exactly once in `layout.tsx`.

## 2. Rules

1. Add the key to **both** locale objects in the **same edit**. Never land a
   `vi`-only or `en`-only key.
2. Keep key ordering and grouping mirrored between the two objects — they are
   read side by side in review.
3. Use the dotted namespace form already in use:
   `<area>.<element>[.<variant>]`, e.g. `hero.stat.focus`, `about.p.web.title`,
   `skills.cat.database`, `projects.kind.mobile`, `projects.helmet.desc`.
4. Add a `// Section` comment above a new group so the two objects stay
   navigable (existing groups: Navbar, Hero, About, Skills, Projects, Contact,
   Notes).
5. Never put JSX or markup inside a translation value. Plain strings only.
6. Never translate brand names, product names, technology names, or handles:
   `Next.js`, `Tailwind CSS`, `GitHub`, `HELMO`, `L.D.Chinh`.
7. Numbers, counts and links are **not** in the dictionary (see §4). Do not add
   interpolation syntax — `t()` takes a single string and does no formatting.
8. Do not rename an existing key to "clean it up". Renaming means touching two
   locale objects plus every call site, for zero user-visible gain.

---

## 3. Key families

| Prefix | Used by | Notes |
|---|---|---|
| `nav.*` | `Navbar` | One key per nav label; also reused nowhere else. |
| `hero.*` | `Hero` | `hero.title` / `hero.subtitle` / `hero.title2` are three lines of one headline — keep the sentence readable across all three. `hero.marquee` is repeated twice at runtime and ends with a trailing `• `. |
| `about.*` | `About`, `projects` card badge | Includes the platform cards (`about.p.<web\|mobile\|desktop\|game>.*`) and the four stat labels. |
| `skills.*` | `Skills` | `skills.cat.*` = category titles, `skills.item.*` = chip labels. |
| `projects.*` | `Projects` | `projects.<name>.title` / `.desc` per project, plus `projects.kind.*` and the two action labels. |
| `contact.*` | `Contact`, `Footer` | `contact.footer` is the footer credit line rendered by `Footer`. |
| `notes.*` | `NotesList`, `NoteView`, `Navbar` (`nav.notes`) | UI chrome only: title, subtitle, empty state, back/read labels, date/reading-time labels, language badges, download labels. Note titles, summaries, bodies, and tags are authored content and are **not** translated. |

If you add a new prefix, add it to this table.

## 4. What is deliberately not translated

- **Project tags** (`["C#", ".NET", "Windows API"]`) live in the `projects`
  array in `Projects.tsx`.
- **Stat values** (`"3"`, `"10+"`, `"5+"`, `"8"`, `"1"`) are hardcoded in
  `Hero.tsx` and `About.tsx`; only their labels are translated.
- **Social URLs and handles** in `Contact.tsx` / `Footer.tsx`.
- **Note content** in `content/notes/*.md`: title, summary, body, tags, and
  download labels stay in the language the note was written in. Only the
  surrounding `notes.*` UI strings switch with the toggle. A note is tagged
  `vi` or `en` in frontmatter and shows that badge so readers know what to
  expect.
- **SEO metadata** in `layout.tsx` (title, description, keywords, Open Graph).
  It is English-only and does not react to the toggle.
- **Code-ish strings** such as `L.D.Chinh`, `OpenCode`, `T3 Code`.

## 5. Known quirk: `<html lang="en">`

`layout.tsx` hardcodes `lang="en"` while the default UI language is `vi`.
Consequences today: screen readers announce English pronunciation for
Vietnamese text until the user toggles, and the server-rendered HTML declares
`en`.

If you are asked to fix it, do it in the provider, not by making the layout
dynamic:

```tsx
useEffect(() => {
    document.documentElement.lang = language;
}, [language]);
```

Keep `suppressHydrationWarning` on `<html>`: the client restores a different
language than the server rendered, and that mismatch is intentional.

Do **not** solve this by reading `localStorage` during render, by moving the
provider into `layout`'s render body, or by forcing the page to `dynamic` — all
three trade a small a11y issue for a hydration or caching regression.

## 6. Adding a string (short version)

1. Pick the key following §2.3.
2. Add `"key": "Bản dịch",` to `translations.vi` under the right section.
3. Add `"key": "Translation",` to `translations.en` in the mirrored position.
4. Call `t("key")` in the component; ensure the component has `"use client"`.
5. Toggle both languages and reload to confirm persistence.

Full recipe: `SKILLS.md` §5.

---

## 7. Adding a third language

The type, the toggle UI, and the persistence are all binary today. In order:

1. `type Language = "vi" | "en" | "ja";`
2. Add a `ja: { ... }` object to `translations` with **every** key from `en`.
   Missing keys will silently render raw key names.
3. Replace the binary toggle in `Navbar.tsx` with a selector (a `<select>` or a
   three-item menu). Keep `aria-label="Toggle Language"` or update it to
   `aria-label="Select language"`.
4. Extend the `document.documentElement.lang` effect (§5) so it follows the
   selected language.
5. Consider the default: `useState<Language>("vi")` is the stored initial value.
6. Add the new prefix/locale to §3 and to `SKILLS.md` §5.
7. Check `hero.marquee` and the longest German/Japanese-style strings for
   overflow at 375px — the hero headline is sized for `BUILD THE` / `APP.`.

## 8. Verification

```bash
npx tsc --noEmit     # catches a renamed key only if it is typed — it is not
npm run lint
npm run build
```

TypeScript will **not** catch a missing dictionary key (`t` takes `string`).
Verify manually:

- [ ] Toggle VI → EN: every new string changes.
- [ ] Reload: the choice persists (localStorage key `language`).
- [ ] Search the two locale objects: each new key appears exactly twice.
- [ ] No raw `word.word.word` text visible anywhere on the page.
- [ ] Vietnamese text still reads naturally, with diacritics.
